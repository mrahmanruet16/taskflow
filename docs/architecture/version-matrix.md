## Compatibility Verification

Checked against the official Laravel release notes: https://laravel.com/docs/13.x/releases (fetched 2026-09-28).

Laravel's published PHP support matrix:

| Laravel version | PHP support |
|---|---|
| 10 | 8.1 – 8.3 |
| 11 | 8.2 – 8.4 |
| 12 | 8.2 – 8.5 |
| **13** | **8.3 – 8.5** |

Laravel 13 was the latest stable major release at the time of this check (released 2026-03-17, "Laravel 13.x requires a minimum PHP version of 8.3" per the official release notes). PHP 8.5.11 falls within Laravel 13's supported range (8.3–8.5), so Laravel 13 was selected — matching the target named in the project brief.

`composer.json` generated by the installer pins:

```json
"php": "^8.3",
"laravel/framework": "^13.17"
```

No prerelease, alpha, beta, RC, or nightly version was used. `dev-master` and `13.x-dev` branches seen in `composer show --all` were explicitly not selected; `v13.33.0` (a tagged stable release) was installed.

## Discrepancy Noted and Resolved

An earlier environment probe in this session (before the Laravel project existed) reported `php --version` as 8.2.34. Re-verification at project bootstrap time showed the `php` binary correctly resolving to 8.5.11 via `update-alternatives`; PHP 8.2 is also installed on this machine (`php8.2` binary, likely a dependency of some other tool/package) but is not the default. This was treated as a blocking question per the project instructions ("if there is a conflict, stop and explain it") and re-verified before any Laravel installation occurred. No conflict existed at the time of installation — `php`, `composer`, and `composer create-project` all resolved to the 8.5-linked toolchain.

## Known Version Mismatches (non-blocking)

- `concurrently@10.0.5` (npm devDependency used by the Laravel `composer run dev` convenience script) declares `engines.node >= 22`; this machine has Node 20.19.6. `npm install` succeeded with an `EBADENGINE` warning only — not a hard failure. `npm run build` and Vite itself work correctly under Node 20. If `composer run dev` (which shells out to `concurrently`) misbehaves later, this is the first place to check.
